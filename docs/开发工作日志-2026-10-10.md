## 一、阶段一：诗词内容结构化扩充（v1.4）

### 1.1 问题诊断

打磨方向讨论后确定"内容扩充与质量"为优先。盘查现有 `poems-data.js`（50 首诗）发现：

**已有**：原文、作者、朝代、学段、主题、名句、二期微课标记
**缺失**：译文、注释、赏析、创作背景、作者小传、体裁

这意味着诗词详情页只能展示半成品，数字导师被问"这首诗什么意思"时也只能回原文 + 名句，体验很差。**内容是古诗词教育项目的根基，这是当前最大的短板。**

### 1.2 方案决策

在四个备选方案中（扩到 100 首 / 先补全 50 首结构化字段 / 两项同时推进 / AI 生成初稿人工修正），最终选择：

> **先补全 50 首的结构化字段（译文/注释/赏析/背景/作者小传/体裁），用智谱 GLM-4-Flash 批量生成初稿，后期由内容组人工校审。**

理由：详情页质量上去比单纯堆数量更实在；50 首是二期微课已覆盖的核心篇目，结构化价值最高。

### 1.3 实施过程

**（1）批量生成脚本 `scripts/enrich_poems.py`**

- 调用智谱 BigModel API（`glm-4-flash`，永久免费模型），`response_format: json_object` 保证输出可解析
- 先生成 5 首样本（覆盖小学/初中/高中、唐诗/宋词、不同主题）检验质量
- 样本暴露 3 个问题后**优化了 prompt**：明确禁止"寓意深刻"类套话、统一注释格式、作者小传要求具体信息
- 全量重跑 50 首，每首约 5-7 秒，整体约 6 分钟
- 工程细节：每完成一首立即 `json.dump` 落盘，防止中途失败丢进度；每次调用间 `sleep(1.2)` 控制频率

**（2）踩坑记录：Python 解析 JS 数组失败**

`poems-data.js` 是 JS 字面量（含单引号、无引号 key），Python 的 `json.loads` 无法直接解析。解决方案：写 `scripts/extract_poems.js` 用 Node 读入后转 JSON 输出，Python 再消费。

**（3）合并与替换**

- `scripts/merge_enriched.py` 把生成的 6 个新字段合并回 JS 数组 → `poems-data.js` 从 20KB 增长到 80KB
- 原文件备份后替换，验证通过后清理备份

**（4）详情页改版 `poems.html`**

弹层从"原文 + 名句 + 敬请期待"升级为 **7 区块结构化展示**：

```
原文（全篇）→ 名句 → 注释（重点字词）→ 译文（白话）
→ 赏析（主题+手法）→ 创作背景 → 作者小传 + 体裁徽章
```

同时加入 `esc()` 转义函数防止 XSS（LLM 生成内容不可全信，必须转义后渲染）。

**（5）首页同步更新**

hero 区统计数字更新："4 大 AI 服务" → "已配结构化赏析 50"。

### 1.4 质量检查与已知问题

写了 `scripts/quality_check.py` 做字段填充完整性检查 + 抽查，发现 **LLM 生成内容的三类典型问题**（已记录，待内容组人工校审）：

1. **幻觉**：李煜（虞美人）的作者小传误列了毛泽东的《浪淘沙·北戴河》
2. **模板化**：创作背景大量套话，如"李白生活在唐代，当时社会繁荣，但诗人自身经历坎坷"
3. **注释选字不精**：如《静夜思》注释了"床""明月"等基础字，却漏掉最有讲解价值的"疑"字辨析

**经验**：AI 批量生成是"初稿加速器"而非"终稿替代品"，内容类项目必须配套人工校审流程。这个问题后续应整理一份"最需润色的 10 首"清单交给内容组。

### 1.5 部署与提交

- `cloudbase hosting deploy` 上传 7 个文件，约 10 秒完成
- commit `da572db`，推送 GitHub 成功

## 二、阶段二：数字导师 v2.0 大升级

### 2.1 需求定义（用户明确提出）

数字导师从单一答疑升级为**真实可用的多模式导师系统**：

1. **三种模式**：课程答疑助教模式 / 个性化学习推荐模式 / 创作辅助模式
2. **多轮对话**：支持追问（如"那他的另一首呢"能理解代词）
3. **历史记录**：会话可保存、可回看
4. **诗人智能体**：可添加喜欢的诗人为专属智能体，如李白、杜甫

### 2.2 云函数 chat v2.0 架构重写

**（1）内置知识库**

新写 `scripts/gen_poems_kb.py`，把 50 首完整结构化数据打包成 `cloudfunctions/chat/poems_data.json`（72KB）随函数代码部署。**云函数从此不依赖数据库**，冷启动即可用，也规避了之前数据库集合未初始化的问题。

**（2）三模式实现**

| 模式 | 入参 | 系统提示策略 |
|---|---|---|
| `qa` 课程答疑助教 | `mode: "qa"` | 知识库检索增强：命中诗篇则把原文/注释/译文/赏析注入上下文，回答附"依据：XX·平台诗词库" |
| `recommend` 个性化推荐 | `mode: "recommend"` | **把 50 首完整目录（标题+作者+学段+主题）注入提示词**，要求只从目录中推荐并说明推荐理由 |
| `creation` 创作辅助 | `mode: "creation"` | 诗词创作导师人设：逐句点评习作的意象/格律/用词，给出具体修改建议 |

推荐模式注入目录是关键设计——**杜绝 LLM 编造库外篇目**。

**（3）七位智能体（第一人称人设）**

小弹（默认导师）+ 李白、杜甫、王维、苏轼、李清照、辛弃疾。每位诗人有独立人设提示词，以第一人称口吻回答（如李白自称"吾乃李太白"）。选中智能体时，自动把**该作者在库中的全部篇目**作为上下文带入，保证诗人"知道自己有哪些作品"。

**（4）多轮对话**

入参从单条 `message` 改为 `messages` 历史数组，云函数取最近 10 条拼入 GLM 请求，实现上下文连贯追问。

**（5）检索逻辑与一次修正**

初版检索函数 `scoreMatch` 有个 bug：用户对李白智能体只说"李白"两个字时，弱匹配误挂了《静夜思》作为来源标签。修正：**智能体模式下的弱匹配（只提作者名、无具体篇目特征）不再强行关联单首诗**，只有标题/名句/原文片段强命中才标注来源。

### 2.3 前端 tutor.html v2.0 重写

- **左侧会话历史栏**：localStorage 持久化（key `gudan_tutor_sessions_v2`），最多保留 50 个会话，支持切换/删除；移动端收起为抽屉
- **模式三选 + 智能体七选**：顶部切换器，切换时自动插入系统提示消息告知用户当前模式/人设
- **快捷提问联动**：默认快捷问题随模式变化（答疑→"《静夜思》表达了什么情感"；推荐→"我喜欢边塞诗，推荐几首"；创作→"帮我看看这首写得怎么样"）
- **诗词库联动**：poems.html 点"问数字导师"跳转 `tutor.html?poem=id`，自动发送该诗的提问
- **多轮上下文发送**：前端保存完整 messages 历史并随请求上送

### 2.4 验证过程（本次升级最值得复盘的部分）

**（1）本地测试 —— 5 个场景全通过（真调 GLM）**

写了 `scripts/test_chat_local.js`：用 `new Function` 沙箱 stub 掉 `@cloudbase/node-sdk`，再 require 云函数代码直接执行主逻辑，本地直调智谱 API。验证场景：

1. 答疑模式带"依据：XX·平台诗词库"来源标注 ✅
2. 多轮追问理解代词（"那他的另一首呢"）✅
3. 李白智能体用第一人称口吻回答 ✅
4. 推荐模式只从 50 首目录中推荐 ✅
5. 杜甫（创作模式）逐句点评习作格律 ✅

这个"本地沙箱跑云函数"的方法**不用部署就能验证业务逻辑**，以后每次改云函数都应先走这一步。

**（2）线上探针 —— 发现 CLI 部署缓存问题（第二次确认）**

浏览器可视化验证因本机 Chrome crashpad 崩溃不可用后，改用更直接的方案：写 `scripts/test_chat_online.js`，读取 CloudBase CLI 本地凭证（`~/.config/.cloudbase/auth.json` 中的临时密钥），用 `@cloudbase/node-sdk` 的 `callFunction` **从外部直接调用线上云函数**。

探针结果：CLI 显示"部署成功"，但线上返回 `agent: undefined`、推荐不带目录——**云端仍在跑 v1.3 旧代码**。这与上次 v1.3 部署时遇到的是同一个坑，至此可以确认：

> **`tcb fn deploy --force` 在本环境下不可靠**：显示成功但代码缓存层未更新。唯一可靠方式是控制台手动上传 zip。

**（3）规避方案**

已打包 `cloudfunctions/chat.zip`（72KB，内含知识库），待控制台"云函数 → chat → 函数代码 → 上传 Zip 包"手动上传。环境变量 `GLM_API_KEY` 不受代码替换影响。

### 2.5 首页联动更新

导师板块从"四大职能"改为**三模式介绍 + 诗人智能体展示**，与新功能对齐；重新部署前端。

## 三、今日踩坑与经验沉淀

| # | 坑 | 解法 | 沉淀 |
|---|---|---|---|
| 1 | Python 无法解析 JS 字面量数组 | Node 中转：`extract_poems.js` 转 JSON | 混合技术栈数据交换统一走 JSON |
| 2 | cmd 下 Python 打印中文乱码 | 输出脚本显式 UTF-8 编码写文件/`sys.stdout.reconfigure` | Windows 脚本默认加编码处理 |
| 3 | 长批量任务怕中断 | 每完成一项立即落盘 + sleep 控频 | 批量 API 任务的标准写法 |
| 4 | **CloudBase CLI 部署缓存**（两次确认） | 控制台手动上传 zip；写**线上探针脚本**用 CLI 凭证外部 callFunction 验证真实部署状态 | CLI "成功"≠云端生效，凡云函数部署必须探针验证 |
| 5 | 本机 agent-browser Chrome 启动即崩（crashpad, exit 3） | 放弃浏览器验证路线，改用 API 探针 | 这台 Windows 机器别再浪费时间试浏览器自动化 |
| 6 | LLM 生成内容有幻觉/套话 | prompt 约束 + 质量检查脚本 + 人工校审流程 | AI 生成是初稿加速器，不是终稿替代品 |
| 7 | 检索弱匹配误挂来源 | 智能体模式下弱匹配不强行关联单首 | 检索阈值要区分"强命中"与"仅提及" |
